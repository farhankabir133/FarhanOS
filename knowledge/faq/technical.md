# FAQ — Technical

## Q: What AI technologies does Farhan use?
A: Farhan works with PyTorch, BERT/RoBERTa, Transformers, LLM prompting frameworks (LangChain, Groq), Wav2Vec 2.0, ONNX quantization, and RAG systems. He has production experience with multimodal fusion and LLM observability.

## Q: What is his preferred frontend stack?
A: React + Next.js + Tailwind CSS v4 + TypeScript. For 3D and animation, he uses Three.js + Framer Motion. For coding UIs, Monaco Editor.

## Q: What backend technologies does he prefer?
A: Node.js/Express for web APIs, FastAPI for ML serving, Go for high-throughput services, and Redis/BullMQ for async queues.

## Q: What databases does he use?
A: PostgreSQL and Supabase for relational data, Redis for caching and queueing, and ChromaDB for vector search in RAG systems.

## Q: Does he use any specific AI/ML tools or frameworks?
A: PyTorch for training, Hugging Face Transformers for fine-tuning, LangChain for RAG orchestration, and Groq API for low-latency inference.

## Q: How does he approach RAG systems?
A: He builds hybrid retrieval systems combining BM25 keyword search with semantic vector search, prioritizes chunking quality over model complexity, and adds metadata filtering for precision.

## Q: What is his experience with LLM evaluation?
A: He has published on perplexity-based adversarial detection and built enterprise observability for 40+ models, including latency, cost, and quality tracking.

## Q: Does he use Docker and Kubernetes?
A: He uses Docker for reproducible environments and GCP/Vercel for deployment. Kubernetes experience exists at a moderate level.

## Q: What architecture patterns does he prefer?
A: Component-based React architecture, async job queues (BullMQ/Redis), FastAPI microservices, and RAG pipelines with clear separation between ingestion, indexing, and retrieval.

## Q: How does he handle testing?
A: Unit and integration testing with Jest/Vitest for frontend, pytest for Python, and manual testing via API contracts and observability dashboards for ML systems.
