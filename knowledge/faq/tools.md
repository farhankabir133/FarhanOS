# FAQ — Tools & Workflow

## Q: What IDE does Farhan use?
A: VS Code for most development. He uses Monaco Editor when building browser-based coding tools (Buddy-Script).

## Q: What operating system does he use?
A: macOS for primary development and Linux for server/ML workloads.

## Q: What terminal does he use?
A: Built-in macOS Terminal and zsh. He values terminal fluency for Git, Docker, and system administration.

## Q: What browser does he use for development?
A: Chrome for debugging and testing, with strong familiarity with DevTools.

## Q: Does he use AI coding assistants?
A: He has built AI coding companions (Buddy-Script) and uses Groq API for inference. He treats AI as a productivity multiplier, not a replacement for understanding.

## Q: What Git workflow does he use?
A: Feature branches with PRs, conventional commits, and GitHub Actions for CI/CD. He values clean history and meaningful commit messages.

## Q: How does he manage dependencies?
A: npm/pnpm for Node.js, pip for Python, and Docker for reproducible environments across languages.

## Q: What monitoring tools does he use?
A: Prometheus and Grafana for OMNIVA AI and backend services. Custom dashboards for ML metrics.

## Q: What communication tools does he prefer?
A: GitHub for code, email for formal outreach, LinkedIn for professional networking, and Discord/Slack for team communication.

## Q: How does he document code?
A: Inline comments for complex logic, README files for project context, and architecture docs for system design.

## Q: Does he use design tools?
A: Limited Figma experience. He designs primarily in code with Tailwind CSS and Framer Motion.

## Q: What is his desk setup?
A: Not documented in knowledge base.

## Q: How does he handle debugging?
A: Browser DevTools, Node.js inspector, Python debugger, and strategic console logging. He favors understanding root causes over patching symptoms.

## Q: What keyboard shortcuts or productivity hacks does he use?
A: Terminal fluency, Git aliases, and VS Code multi-cursor editing. Not an extensive list documented.

## Q: Does he use any project management tools?
A: Not formally documented. He manages work through GitHub issues and milestones.

## Q: What is his code review philosophy?
A: Review for correctness, readability, and architecture fit. He values clear feedback and fast iteration.

## Q: How does he handle technical debt?
A: He prefers avoiding it through clean architecture upfront. When unavoidable, he schedules dedicated refactoring sprints.

## Q: What backup and sync tools does he use?
A: Git for code, cloud storage for documents, and Vercel/GitHub for deployment redundancy.

## Q: Does he use any note-taking apps?
A: Not documented in knowledge base.

## Q: What is his approach to learning new tools?
A: Build a minimum viable project with it, read the source code, and compare against alternatives before adopting in production.
